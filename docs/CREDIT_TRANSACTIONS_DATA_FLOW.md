# Credit Transactions Data Flow Explanation

## Overview

This document explains how credit transaction data is generated and how the fields in the API response are calculated.

## API Endpoint

```
GET /api/credits/transactions
```

## Sample Response Data


## Data Generation Flow

### 1. Transaction Creation

When a subscription is purchased or credits are granted, the system creates a transaction record:

**Location**: `backend/src/services/credit.service.ts` → `grantSubscriptionCredits()`

```typescript
async grantSubscriptionCredits(
  tenantId: string,
  amount: number,           // e.g., 2000 credits
  subscriptionId: string,
  expiresAt: Date,
  userId?: string,
) {
  // Step 1: Get or create credit account
  const account = await this.getOrCreateCreditAccount(tenantId, userId);

  // Step 2: Update account balances
  account.subscriptionCredits += amount;  // Add to subscription credits
  account.currentBalance += amount;       // Add to current balance
  account.lifetimeEarned += amount;       // Track lifetime earned
  account.lastRefreshDate = new Date();
  account.nextRefreshDate = expiresAt;

  await this.creditAccountRepository.save(account);

  // Step 3: Create transaction record
  const transaction = this.creditTransactionRepository.create({
    tenantId,
    creditAccountId: account.id,
    type: CreditTransactionType.SUBSCRIPTION_GRANT,
    amount,                              // 2000
    balanceAfter: account.currentBalance, // 3000 (if previous balance was 1000)
    description: 'Monthly subscription credits granted',
    subscriptionId,
    expiresAt,
    metadata: { grantedAt: new Date().toISOString() },
  });

  return await this.creditTransactionRepository.save(transaction);
}
```

### 2. Field Calculations

#### Transaction Fields

| Field | Description | How It's Generated |
|-------|-------------|-------------------|
| `amount` | Credits added/removed in this transaction | Passed as parameter when granting credits (e.g., 2000) |
| `balanceAfter` | Account balance after this transaction | `account.currentBalance` after adding the amount |
| `type` | Transaction type | Set based on operation (SUBSCRIPTION_GRANT, PURCHASE, CONSUMPTION, etc.) |
| `description` | Human-readable description | Set based on transaction type |
| `createdAt` | When transaction occurred | Auto-generated by database |

#### Credit Account Fields (Included in Response)

| Field | Description | How It's Calculated |
|-------|-------------|-------------------|
| `currentBalance` | Total credits available | `subscriptionCredits + purchasedCredits + bonusCredits - consumed` |
| `subscriptionCredits` | Credits from subscriptions | Incremented when subscription credits are granted |
| `purchasedCredits` | Credits from direct purchases | Incremented when credits are purchased |
| `bonusCredits` | Promotional credits | Incremented when bonus credits are granted |
| `lifetimeEarned` | Total credits ever received | Sum of all credits granted (never decreases) |
| `lifetimeSpent` | Total credits consumed | Sum of all credits consumed for operations |
| `revenueFromPartnerSales` | Revenue from partner plan sales | Updated when truck owners purchase partner plans |
| `totalPartnersSold` | Number of partners who purchased | Count of partner plan purchases |
| `creditsAllocatedToPartners` | Credits allocated to partners | Sum of credits allocated to all partners |

## Transaction Types

### Credit Transactions (Positive Amount)

1. **SUBSCRIPTION_GRANT**
   - When: Subscription is purchased or renewed
   - Amount: Credits from subscription plan
   - Example: 5000 credits from "Pro Max" plan

2. **PURCHASE**
   - When: Direct credit purchase
   - Amount: Credits purchased
   - Example: 1000 credits bought for $1000

3. **BONUS**
   - When: Promotional credits granted
   - Amount: Bonus credits
   - Example: 500 bonus credits for referral

4. **REFUND**
   - When: Credits refunded for cancelled service
   - Amount: Refunded credits
   - Example: 200 credits refunded

### Debit Transactions (Negative Amount)

1. **CONSUMPTION**
   - When: Credits used for operations
   - Amount: Credits consumed
   - Example: -500 credits for cargo transport

2. **EXPIRY**
   - When: Credits expire
   - Amount: Expired credits
   - Example: -100 expired credits

3. **ADJUSTMENT**
   - When: Manual adjustment by admin
   - Amount: Adjustment amount (can be positive or negative)
   - Example: -50 credits correction

### 2. Controller Processing

```typescript
async getTransactions(@Request() req) {
  const tenantId = req.user.tenantId;
  const userId = req.user.id;
  const userRole = req.user.role;

  // For TRUCK_OWNER, fetch their personal transactions
  if (userRole === 'TRUCK_OWNER') {
    filters.userId = userId;
  }

  const result = await this.creditService.getTransactionHistory(tenantId, filters);
  
  return {
    success: true,
    data: result.transactions,
    pagination: { total, limit, offset }
  };
}
```

### 3. Service Query
**File**: `backend/src/services/credit.service.ts`

```typescript
async getTransactionHistory(tenantId: string, filters?: any) {
  const query = this.creditTransactionRepository
    .createQueryBuilder('transaction')
    .leftJoinAndSelect('transaction.creditAccount', 'creditAccount')
    .where('transaction.tenantId = :tenantId', { tenantId });

  if (filters?.userId) {
    query.andWhere('transaction.userId = :userId', { userId: filters.userId });
  }

  query.orderBy('transaction.createdAt', 'DESC');

  const transactions = await query.getMany();
  return { transactions, total: transactions.length };
}
```

### 4. Database Query
```sql
SELECT 
  t.*,
  ca.current_balance,
  ca.subscription_credits,
  ca.purchased_credits,
  ca.bonus_credits,
  ca.lifetime_earned,
  ca.lifetime_spent,
  ca.revenue_from_partner_sales,
  ca.total_partners_sold,
  ca.credits_allocated_to_partners
FROM credit_transactions t
LEFT JOIN credit_accounts ca ON t.credit_account_id = ca.id
WHERE t.tenant_id = ?
ORDER BY t.created_at DESC
```

## Why Different Values?

### Scenario: Transaction shows amount=2000, but balance=3000

This happens when:
1. **Previous Balance**: Account had 1000 credits before
2. **Transaction Amount**: 2000 credits were added
3. **Balance After**: 1000 + 2000 = 3000 credits

The transaction record captures:
- `amount`: What changed in THIS transaction (2000)
- `balanceAfter`: Total balance AFTER this transaction (3000)

### Scenario: Revenue shows 0.00 for truck owner

This is correct because:
- `revenueFromPartnerSales`: Only tracked for TENANT ADMIN (tenant-level account)
- Truck owners don't sell partner plans, so their revenue is always 0
- Revenue is tracked separately in the tenant-level credit account (userId = NULL)

**Interpretation:**
1. This transaction added 2000 credits
2. After this transaction, balance became 3000
3. This means previous balance was 1000 (3000 - 2000 = 1000)
4. All 3000 credits are from subscriptions (no purchases or bonuses)
5. No credits have been consumed yet (lifetimeSpent = 0)
6. This is a truck owner account (revenue fields are 0)

## Summary

The credit transaction system:
1. **Creates transaction records** when credits are granted, consumed, or adjusted
2. **Updates credit account** balances in real-time
3. **Tracks history** of all credit movements
4. **Maintains integrity** by recording balance after each transaction
5. **Separates concerns** between operational credits and financial revenue

All data is generated through database operations triggered by business events (subscriptions, purchases, consumption, etc.), ensuring accuracy and auditability.
